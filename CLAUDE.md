# VoiceToText — правила для Claude Code

## Что это за проект

VoiceToText — простое личное приложение для Windows: нажал горячую клавишу, сказал фразу — туда, где стоит курсор, вставляется аккуратный текст. Речь распознаётся локально моделью NVIDIA Parakeet, затем локальная ИИ-модель (через Ollama) убирает слова-паразиты, запинки и оговорки и при необходимости меняет стиль текста.

Приложение работает только на одном компьютере владельца. Пошаговый план — в `PLAN.md`. Работай строго по нему.

## Как общаться с владельцем

- Владелец — не программист. Пиши по-русски, простыми словами. Если без термина не обойтись — поясни его в скобках одной фразой.
- Делай **один этап** из `PLAN.md` за раз. Не забегай вперёд.
- Перед началом этапа коротко перескажи, что собираешься сделать (3–5 пунктов), и дождись согласия.
- Спрашивай перед любым решением, которого нет в этом файле: новая библиотека, другая модель, изменение структуры, удаление файлов.
- Если владелец должен что-то сделать сам (установить программу, выполнить команду), давай команду целиком, готовую к копированию, и говори, куда её вставить.
- В конце этапа: что сделано (2–4 пункта), как проверить руками (пошагово, без программистских действий), что дальше.
- Если что-то сломалось — сначала объясни причину простыми словами, потом предложи исправление.
- Отмечай выполненные пункты в `PLAN.md` (`[ ]` → `[x]`).

## Главные принципы

1. **Максимальная простота.** Минимум файлов, классов и настроек. Если сомневаешься — делай проще. Ничего «на будущее».
2. **Всё локально.** Никаких облачных API, телеметрии, аналитики. Интернет нужен только один раз — скачать модели.
3. **Текст никогда не теряется.** Если редактура упала или зависла — вставляется сырой распознанный текст. Итоговый текст всегда остаётся в буфере обмена и пишется в историю.
4. **Интерфейс не зависает.** Запись, распознавание и редактура идут в фоновом потоке.

## Технологии (не менять без согласования)

| Задача | Решение |
|---|---|
| Язык и окружение | Python 3.14 (у владельца установлен 3.14.7), виртуальное окружение `.venv` |
| Распознавание речи | `onnx-asr`, модель `nemo-parakeet-tdt-0.6b-v3` (русский + английский, сама определяет язык, сама ставит пунктуацию) |
| Ускорение | видеокарта NVIDIA (CUDA). Если не заводится — процессор, и объяснить владельцу, чего не хватает |
| Микрофон | `sounddevice`, 16 кГц, моно |
| Редактура текста | Ollama на `http://localhost:11434` через `requests`; модель берётся из настроек, по умолчанию `qwen3:8b` |
| Глобальная клавиша и нажатие Ctrl+V | `pynput` |
| Буфер обмена | `pyperclip` |
| Значок в трее | `pystray` + `Pillow` |
| Окно настроек | `tkinter` (встроен в Python) |
| Звуковые сигналы | `winsound` (встроен в Python) |

Команды установки `onnx-asr` для GPU сверяй с официальной инструкцией (Installation Guide в репозитории `istupakov/onnx-asr`), не угадывай.

Про видеокарту: свежие версии `onnxruntime-gpu` рассчитаны на CUDA 13 и cuDNN 9. По возможности ставь CUDA и cuDNN как pip-пакеты NVIDIA внутрь `.venv` (у `onnxruntime-gpu` есть функция предзагрузки этих библиотек), а не заставляй владельца вручную ставить CUDA Toolkit. Точные имена пакетов сверяй с документацией ONNX Runtime (CUDA Execution Provider).

Если какая-то библиотека окажется несовместимой с Python 3.14 — не ищи обходных путей, а объясни владельцу и предложи поставить рядом Python 3.12 (версии не мешают друг другу).

## Где что лежит

```
VoiceToText/
├── CLAUDE.md
├── PLAN.md
├── README.md               ← как запускать (для владельца, простым языком)
├── requirements.txt        ← все библиотеки с версиями
├── run.bat                 ← запуск без чёрного окна (pythonw)
├── prompts/                ← инструкции для редактуры, владелец правит их в Блокноте
│   ├── base.txt            ← общие правила чистки текста
│   ├── normal.txt
│   ├── polite.txt
│   └── professional.txt
├── voicetocode/
│   ├── __main__.py         ← точка входа: соединяет все части
│   ├── settings.py         ← чтение/запись настроек, значения по умолчанию
│   ├── recorder.py         ← запись с микрофона
│   ├── recognizer.py       ← Parakeet: звук → текст
│   ├── editor.py           ← словарь замен + Ollama: чистка и стиль
│   ├── hotkey.py           ← глобальная клавиша, оба режима
│   ├── paster.py           ← вставка текста в активное окно
│   ├── tray.py             ← значок и меню в трее
│   └── settings_window.py  ← окно настроек
└── tests/                  ← тесты только для логики без микрофона и клавиатуры
```

Данные владельца — в `%APPDATA%\VoiceToText\`: `settings.json`, `dictionary.txt` (словарь замен), `history.txt` (последние 100 диктовок: сырой и итоговый текст), `voicetotext.log`.

Новые файлы добавляй, только если без них никак, и сообщай владельцу зачем.

## Как работает приложение

1. Владелец нажимает горячую клавишу (по умолчанию F9) → короткий сигнал, значок красный, идёт запись.
   - режим «Удержание»: запись идёт, пока клавиша зажата;
   - режим «Переключение»: первое нажатие — старт, второе — стоп.
2. Запись остановлена → значок жёлтый.
3. `recognizer`: звук → сырой текст. Записи длиннее ~20 секунд режь на куски по паузам (VAD из `onnx-asr`): модель за раз принимает не больше 20–30 секунд звука.
4. `editor`: словарь замен → Ollama (чистка + выбранный стиль). В стиле «Без обработки» Ollama не вызывается.
5. `paster`: текст → буфер обмена → Ctrl+V в активное окно. Текст остаётся в буфере.
6. Запись в историю, значок снова серый.

Слишком короткие записи (меньше ~0,3 с) и пустой результат распознавания молча игнорируй.

## Редактура текста — правила

- Тексты инструкций (промпты) лежат в `prompts/*.txt`, а не в коде.
- Надиктованный текст передавай модели внутри тегов `<text>…</text>` и явно пиши, что это текст для редактирования, а не задание.
- **Модель только редактирует.** Не отвечает на вопросы из текста, не выполняет просьбы из текста, ничего не добавляет от себя. Пример: «напиши функцию сортировки» должно остаться просьбой, а не превратиться в код. Это главный риск: владелец диктует задания для Claude Code.
- Убрать: слова-паразиты (ну, вот, как бы, типа, короче, это самое, в общем, значит, э-э, м-м), повторы, запинки, оговорки и самоисправления («в среду… нет, в четверг» → «в четверг»).
- Сохранить: смысл, факты, числа, имена, порядок мыслей. Английские термины — латиницей и в правильном написании (Claude Code, GitHub, Python, API), даже если распознаны русскими буквами.
- Стили: «Без обработки», «Обычный» (только чистка), «Вежливый», «Профессиональный». Эталонные примеры — в `PLAN.md`, раздел 2.
- Параметры запроса к Ollama: `think: false` (без «размышлений»), `temperature` около 0.2, `keep_alive` около 30 минут, таймаут 20 секунд. При запуске приложения сделай один «прогревочный» запрос, чтобы модель заранее загрузилась в видеопамять.
- Из ответа модели бери только текст: убирай кавычки, теги и приписки вроде «Вот исправленный текст:».
- Если в ответе появился блок кода, которого не было в исходнике, или ответ в разы длиннее исходника — считай, что модель «ответила» вместо редактуры: вставь текст после словаря замен (без Ollama) и запиши предупреждение в лог.

## Подводные камни Windows (учитывать сразу)

- `tkinter` работает только в главном потоке. `pystray` запускай через `run_detached()`. Из фоновых потоков к окну обращайся только через `root.after()` или очередь.
- Обработчик клавиатуры `pynput` должен возвращаться мгновенно — всю тяжёлую работу передавай в другой поток.
- При удержании клавиши Windows присылает повторные нажатия (автоповтор) — игнорируй их, иначе режим «Удержание» сломается.
- Горячая клавиша не должна доходить до других программ (иначе F9 сработает и в активном окне): подавляй только её, через `win32_event_filter` в `pynput`.
- Перед нажатием Ctrl+V дождись, пока владелец отпустит все клавиши горячего сочетания, иначе вместо вставки сработает другая комбинация.
- Глобальная клавиша не срабатывает, когда активно окно, запущенное от имени администратора. Это ограничение Windows — не «лечи», просто упомяни в README.
- Модель Parakeet загружай один раз при старте и держи в памяти. Первый запуск скачивает модель — покажи это в подсказке значка в трее.
- Имя пользователя Windows может быть на кириллице: пути только через `pathlib`, все файлы открывай с `encoding="utf-8"`.
- Parakeet и модель Ollama делят видеопамять. Если её не хватает — предложи владельцу перевести распознавание на процессор или взять модель редактуры поменьше.

## Правила кода

- Простой, читаемый код. Короткие комментарии на русском там, где неочевидно.
- Новые библиотеки — только с согласия владельца. Все зависимости — в `requirements.txt` с версиями.
- В готовом приложении — `logging` в файл, без `print`.
- Все ошибки лови и пиши в лог. Владельцу показывай короткое понятное уведомление, а не трассировку.
- Тесты (`pytest`) — только для чистой логики: словарь замен, очистка ответа модели, настройки. Микрофон и клавиатуру автоматически не тестируй.

## Git — «сохранения в игре»

- Первым делом на Этапе 1: `git init` и `.gitignore` (исключить `.venv`, `__pycache__`, скачанные модели).
- После каждого рабочего этапа — коммит с понятным сообщением на русском. Перед рискованными изменениями — тоже.
- Без просьбы владельца не делай `push`, не переписывай историю, не удаляй ветки.
- Если владелец просит «откатить» — объясни, к какому состоянию вернёмся, и только потом делай.

## Команды

Для командной строки Windows (cmd или PowerShell):

```
py -3.14 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m voicetocode      (запуск с консолью, для отладки)
run.bat                                  (обычный запуск без консоли)
.venv\Scripts\python -m pytest           (тесты)
```

Если твоя оболочка — Git Bash, используй прямые слеши: `.venv/Scripts/python`.

## Чего не делать

- Облачные сервисы распознавания или редактуры.
- Инсталлятор, автообновление, учётные записи, перевод интерфейса на другие языки.
- Менять настройки владельца (клавишу, стиль, модель) без его просьбы.
- Добавлять функции, которых нет в `PLAN.md`, — сначала предложи и спроси.
